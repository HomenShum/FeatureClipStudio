TrialScope

Every number on screen came from the registry.

Not one was added up, guessed at, or written by a model. This is how that was held, what it cost, and where it nearly broke.

The rule

The model picks which questions to ask.
It never answers one.

Each answer is a totalCount the site returned.

How you check it

Every step keeps the web address it used.

Send that address yourself. Same number, or the rule is broken.

Decision 1 · the invariant

Probe for counts. Never compute them.

A chart with six bars is six separate questions to ClinicalTrials.gov, not one question and five sums.

Chosen

One count probe per bucket.
countTotal=true&pageSize=1

Rejected

Fetch a page of studies and group them locally. Faster, one request.

What it costs

N requests where one would do. Pacing, caching and single-flight exist only to pay for this.

What would refute it

Replay any trace row and get a different number.

The evals re-probe through a separate client, so the system cannot confirm its own arithmetic.

Decision 2 · storage

No database. On purpose.

The registry is the source of truth, and a copy of it is a promise to be wrong later.

Chosen

Ask live. Cache in memory, per tenant, for minutes.

Rejected

Mirror the registry into Postgres and query that.

What it costs

Latency on a cold cache, and a hard ceiling on question shapes: if the API cannot express it, neither can we.

What would refute it

A question users actually ask that the count API cannot answer at all.

One appeared: two-hop peer questions. It forced an entity index — and that index proposes, it never answers.

Decision 3 · the graph

Neo4j was the right answer to the wrong question.

It matched the stack on paper. It could not be deployed the way this service deploys.

The blocker, measured

Bolt is raw TCP on 7687. Cloud Run ingress serves HTTP/1, HTTP/2, gRPC and WebSockets — and nothing else.

Chosen

An in-process index is the default. Neo4j stays supported, for anyone who runs one.

The trap avoided

Two backends invite two behaviours that quietly disagree.

What would refute it

Rankings that differ between them.

So the test runs both and diffs the output — never asserts a paraphrase of the Cypher.

Decision 4 · the honest chart

The buckets do not add up, and it says so.

A trial can be Phase 2 and Phase 3. Sum the bars and you get a number that means nothing.

The belief that was wrong

"If the buckets sum to the total, they must be exclusive."

The measurement that killed it

Overlap and missing values cancel exactly. The sum matches while the buckets overlap.

Chosen

Exclusivity is a property of the dimension, asserted from the API's field semantics — never inferred from arithmetic.

The consequence

buckets_are_exclusive = false blocks pie and 100% stacked marks at render time.

Decision 5 · many tenants, one quota

Jitter felt like the fix. It measured like nothing.

Fairness across tenants sharing one upstream budget, by Jain index — 1.0 is perfectly fair.

Tried first

Randomised backoff, so tenants stop colliding.

0.139 → 0.150essentially unchanged

What worked

Order arrivals fairly — FIFO across tenants.

→ 0.986near perfect

The other wrong belief

max_tenant_share caps work in flight. A tenant that grabs and releases instantly never hits the cap, and still starves everyone.

How it is checked

A concurrency ramp, offline, every run.

A synchronous mock hides the race: 8 calls collapse to 1 and the bug reports itself as fixed.

The failure worth naming

Correct, tested, documented — and never called.

The per-tenant cache closed a timing side-channel measured at 31,377x. It had passing tests. It had a README section. Nothing in the running service constructed it.

Why it survived review

Every signal a reviewer normally trusts was green. Tests passing is not the same as code running.

What changed because of it

A surface with no screenshot has not been checked, however green its tests are.

What it caught next

Two user-visible defects found only because someone asked for a screenshot that did not exist.

The standing rule

Adversarial review before anything is called done — hunting weakened checks, unwired mechanisms, and numbers measured before the change they justify.

How to read this repo

Twenty-seven beliefs, each with the measurement that killed it and the change it forced. It is more useful than the current values, because it shows which intuitions do not survive here.
