# Conventions

These are the rules the existing code actually follows. Where a rule was learned from
a specific failure, the failure is named — that is the convention here too.

## Naming

| Pattern | Meaning |
|---|---|
| `walkthrough.<target>.mjs` | a capture program: drives a live app |
| `walkthrough.<target>.specs.mjs` | **data**, not a program: the demo script for one app |
| `src/walkthrough.*.data.js` | **generated**; overwritten whole by a capture run |
| `WT-`, `WTC-`, `WTG-` prefixes | single-pane, two-pane collab, four-up grid |
| `probe-*.mjs` | a gate that renders or measures something and exits non-zero on failure |
| `zz-fail.png` | a forensic screenshot; sorts last, never referenced by generated data |

Remotion composition ids may not contain `_`.

## Every file opens with why it exists

Not what it does — why. The top-of-file comment in `walkthrough.mjs`,
`probe-opening-frame.mjs`, `iterate.mjs` and `clip.mjs` each states the defect or
decision that made the file necessary. Keep doing this. A file whose header only
restates its own name has told the next reader nothing.

## Comments record the bug, not the behaviour

The distinctive habit in this codebase is a comment that preserves a counterexample:

```js
// An unrecognised act used to fall out of this chain doing NOTHING, with no
// error. A spec written with `scroll` instead of `scrollY` therefore produced
// a clip where the page never moved — four captioned steps over one frozen
// viewport, which looks exactly like a walkthrough that worked.
```
— `walkthrough.mjs:101`

Do not delete these while tidying. They are the reason the guard below them is not
"defensive programming"; each one names an artifact that shipped.

## Fail loudly rather than produce empty evidence

The single strongest rule here. **A tool that silently does nothing is worse than one
that crashes, because it emits something that passes for evidence.** Concretely:

- Throw on an unknown op; list the valid vocabulary in the message
  (`walkthrough.mjs:108`).
- Throw when a selector matches nothing, rather than `.catch(() => {})`
  (`walkthrough.mjs:95`).
- Require a *presence* proof before any negative assertion or any capture
  (`walkthrough.mjs:32`, `walkthrough.mjs:124`).
- Print the count, not just "ok" — `check.mjs` prints `parsed 37/37` so a gate cannot
  quietly shrink its own coverage.

## Rehearse before you write a spec

Every caption in `walkthrough.specs.mjs` was written after watching that step run,
not from reading the DOM. This is a working practice, not code:

1. Open the target app in a browser and do the journey by hand.
2. Write the ops for what you just saw.
3. `npm run capture`, then `npm run studio` and scrub — the studio is far cheaper
   than a render.
4. Only then `npm run render` or `npm run clip`.

Scripts that automated step 1 against two specific products used to live in the root
(`survey-*.mjs`, `rehearse-*.mjs`, `probe-room-routes.mjs`). They were deleted on
2026-08-13 because they imported a sibling checkout that a clone does not have and
hard-coded another product's URLs; `git show 341fd20:survey-journeys.mjs` still has
them if you want the shape.

## Errors carry their own vocabulary

An error message should tell the reader what *would* have worked:

```js
throw new Error(
  `unknown act "${a.act}" — valid: fill, click, upload, sleep, waitText, notRunning, ` +
  `scrollTop, scrollY, scrollText, scrollLastChat, scrollEl`);
```

If you add an op, add it to that list in the same commit. That message is the op
vocabulary's only documentation.

## Configuration is environment variables with defaults, never a config file

`DEMO_URL`, `WT_ONLY`, `VISUAL_URL`, `ROOMOS_URL`, `NODEVOICE_URL`, `VOICE`,
`GEMINI_API_KEY`. Each is read at its point of use with `process.env.X || <default>`.
There is no config loader and no settings file; do not add one for a value that has a
sensible default.

## Numbers in the source cite where they came from

```js
const VOICE = process.env.VOICE || "en_US-ryan-high";  // 23% faster speech, 0 overruns
const gate  = flag("gate", "28");                      // 28/40 — see README for where this came from
config: { stiffness: 400, damping: 45 }                // MagicUI SmoothCursor params
```

A tuned constant with no provenance is the next person's mystery. Leave the reason.

## Style

Two-space indent, double quotes, semicolons, arrow-function consts, `async`/`await`
over `.then`. Short helper lambdas at the top of a file, the entry `run()` at the
bottom, invoked as `run().catch((e) => { console.error(e); process.exit(1); });`.
There is no linter and no formatter configured — match the file you are editing.

## Generated files

Anything in `src/*.data.js` is generated and carries an
`// AUTO-GENERATED by … — do not edit by hand.` header. If you need different holds,
change them with `npm run retime` or let `clip.mjs` fit them to the narration; both
rewrite the file through the same path the generator uses.
